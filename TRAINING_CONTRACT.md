# Training workspace implementation contract

This is a development contract; the README describes user-facing behavior. Training data belongs to the authenticated member, independently of their linked Riot account. No Riot calls, uploaded videos, AI analysis, live decision support, or playable League clone. The old simulator is no longer loaded. Existing goals and match analytics remain intact.

## API

All routes require the existing authenticated session. JSON mutations require `application/json`, reject explicit cross-origin requests and are bounded to 40 KiB by `training_api.py`. Unknown/duplicate JSON keys and query fields are rejected. Responses use `Cache-Control: no-store, private` and `Vary: Cookie`. `username`/owner never comes from a body. No private training data appears in player/cohort endpoints.

- `GET /api/training`: `{catalog:{workouts,starter_puzzles}, entries:{plans:[],sessions:[],reviews:[],lessons:[],puzzles:[],attempts:[],experiments:[],boards:[]}, teams:[], invitations:[], limits:{...}}`. Personal lists only, max 50 newest by creation per kind; `limits.has_more` maps each kind to a truncation flag. `limits` also reports `per_member`, `per_team`, `teams_per_member`, `members_per_team`, `entry_bytes`, `page_size`, `member_count` (personal records plus authored team docs in currently active memberships), `personal_count` and `remaining`.
- `GET /api/training/entries/{kind}?team_id=...&offset=0&limit=50`: `{entries:[],has_more:boolean}`. Without team_id only personal entries. Team reads require accepted membership at read time.
- `POST /api/training/entries/{kind}`: `{data:{...},team_id:null}` -> `{entry}`.
- `PUT /api/training/entries/{kind}/{id}`: `{data:{...},revision:positive_int}` -> `{entry}`. Full validated replacement, no changing team/owner; lesson scheduling fields remain server-owned. Stale revision is 409; revisions range from 1 to 2^31−1. The upper limit blocks further increments, not deletion.
- `DELETE /api/training/entries/{kind}/{id}?revision=N`: `{ok:true}`. Creator-only personal delete; team owner or document creator can delete team docs. Inaccessible IDs return 404, not revealing existence.
- `POST /api/training/lessons/{id}/grade`: `{revision,rating:'again'|'good'|'easy'}` -> `{entry}`. Server calculates due/interval/repetitions.
- `GET /api/training/export`: `{version:1,username,exported,entries:{...}}`, all member's personal records beyond initial pages, no team documents, cached match/timeline data, local calibration or video. Includes `tracking:[{plan_id,owner,puuid,role,champion_id,queue_id,patch,started,games,baseline_ids:[match_id,...]}]` only when this member has personal plan links; otherwise the key is omitted. The captured PUUID is the member's own linked-account identifier, not a third-party lookup.
- `POST /api/training/teams`: `{name}` -> `{team}`.
- `POST /api/training/teams/{id}/invite`: `{username}` -> `{ok:true}`. Owner only; invite existing member, membership requires acceptance.
- `POST /api/training/teams/{id}/accept`: `{}` -> `{team}`.
- `DELETE /api/training/teams/{id}/members/{username}`: owner removes or member leaves; owner must delete team rather than leave. Pending invitations can be declined/cancelled the same way.
- `DELETE /api/training/teams/{id}`: owner only, cascade team docs/invites.
- `GET /api/training/teams/{id}`: `{team,entries:{reviews:[],puzzles:[],boards:[]},has_more:{reviews:boolean,puzzles:boolean,boards:boolean}}`, accepted membership required. Lists contain at most 50 newest by creation per kind; use per-kind list pagination for older docs.

Record: `{id,kind,owner,team_id,revision,created,updated,data}`; `created`/`updated` are integer Unix seconds. Team: `{id,name,owner,created,members:[{username,status:'active'|'invited'}]}`. Invitation: `{team_id,team_name,owner,created}`; no team documents/member roster before acceptance.

### Cached match routes (six method/path pairs)

These routes in `training_api.py` delegate to `training_matches.py` and retain the same session, strict query/body, same-origin mutation and private-response rules above. Plans must be personal and owned by the authenticated member (archived plans remain accessible); inaccessible plan IDs return 404. The account is always resolved from the member's current link, never from caller-supplied username/PUUID. This self-link is not proof of Riot account ownership.

- `GET /api/training/matches/options` (no query fields): `{account:{game_name,tag_line,platform}|null,patches:[string,...],champions:[{id,name},...],queues:[{id,label},...],roles:[{id,label},...],available:boolean,reason:string|null,truncated:boolean}`. Patch/champion options come only from verified completed matches of the currently linked account in a bounded cache sample. Champion names are fallback labels such as `Champion 103`; the browser may resolve them using existing metadata. Missing link/cache/sample is reported honestly, not fetched.
- `GET /api/training/plans/{plan_id}/matches` (no query fields): returns the progress object below, without `entry`. An absent link, unlinked/switched account or unavailable cache returns `available:false` with `reason`, no cached rows and null metric means/differences. Captured tracking metadata and the frozen baseline count can remain present even when cache progress is hidden.
- `POST /api/training/plans/{plan_id}/matches`: `{revision,role,champion_id,queue_id,patch}` -> the progress object **plus** `entry` (the revised saved plan). All five fields are required: `revision` is a strict positive integer up to 2^31−1; `role` is `TOP|JUNGLE|MIDDLE|BOTTOM|UTILITY`; `champion_id` is null (any champion) or an integer 1..2^31−1; `queue_id` is one of 420 (Ranked Solo), 440 (Ranked Flex), 400 (Normal Draft), 490 (Quickplay); `patch` is nonblank, control-free text up to 32 characters. Patch and any non-null champion must be among the current cached options. Start/restart requires a linked account (409 otherwise), returns 503 if the cache cannot be read, and atomically replaces this plan's link and bumps the plan revision/updated timestamp, without changing plan data. Stale revisions are 409. No `games`, `started`, baseline IDs or account identifiers are accepted in the body.
- `DELETE /api/training/plans/{plan_id}/matches?revision=N`: `{ok:true,entry}`. The required query revision follows the existing strict integer/stale-revision rules. Removes only the tracking link and bumps the plan revision/updated timestamp, even if no link remains; preserves the plan, sessions, reviews and other notes. Does not need a linked account or a readable cache.
- `GET /api/training/review-queue?plan_id=...`: `{available,reason,scope,games_considered,timelines_available,prompts:[],missing_timelines,note,truncated}`. `plan_id` is optional and must be nonblank valid identifier text when supplied. With a linked plan, `scope` is `{plan_id,started,games,role,champion_id,queue_id,patch}` and the queue uses that captured subsequent-game window, not the baseline or current plan edits. Without `plan_id`, `scope` is `{plan_id:null,queue_id:420,games:10}` and the queue uses the newest ten verified completed cached solo games across all roles, champions and patches. A supplied plan without tracking is unavailable, not silently replaced with recent solo games; its scope contains `plan_id` and the default `queue_id/games` fields. A missing/switched account also makes a tracked scope unavailable. At most six prompts total and three per game; usable/missing timeline counts cover all considered games even after the prompt cap is reached.
- `GET /api/training/review-context/{match_id}` (no query fields): `{match,available,reason,events:[],prompts:[],note}`. The match must be a verified completed supported Rift match containing the currently linked account. Unknown, foreign, unlinked, unfinished or unsupported matches and unavailable caches all return the same non-disclosing 404 (`Completed match not found`). A valid own match without a usable cached timeline returns 200 with `available:false`, a reason and empty events/prompts; it never fetches a timeline. At most 80 events and three prompts. Context is independent of whether the member has a plan or tracking link.

Shared response shapes:

- `tracking`: `{started,games,role,champion_id,queue_id,patch}` or null. `started` is Unix seconds retaining the full fractional `time.time()` value (do not round); `games` is the saved plan's captured 1..20 window. Normal progress/options/queue/context responses do not expose PUUIDs or the stored link row.
- Progress: `{available:boolean,reason:string|null,tracking,baseline:{games,rows:[]},practice:{games,rows:[]},metrics:[],note:string,truncated:boolean}`. A match row is `{match_id,game_start,duration,champion_id,role,patch,queue_id,win:boolean|null,values:{cs10:number|null,deaths:number|null,early_deaths:number|null,lane_gold10:number|null}}`. `game_start` is Unix **milliseconds**; `duration` and prompt/event `seconds` are match-clock seconds. A vanished/invalid frozen baseline row keeps `{match_id,missing:true}` with all other match fields and metric values null, never a substitute match.
- Each metric is `{key,label,unit,baseline:{mean:number|null,n:int},practice:{mean:number|null,n:int},difference:number|null}`. Difference is practice mean minus baseline mean only when both samples have observations. `n` counts non-null values for that metric, not all games. Deaths/early deaths apply to all roles; lane CS at 10 and lane gold difference at 10 apply to top/middle/bottom, jungle CS before 10 to jungle; support has no CS/lane-gold comparison. Unavailable/inapplicable measurements and empty groups are null, not zero; observed zero remains valid. Early-death counts require actual cached frame coverage through min(600 seconds, match duration); a shorter partial timeline remains null even if it records a known early death. Lane-gold samples use the nearest complete frame within the existing 15-second tolerance. Malformed cached counters outside 0..1,000,000,000 are unavailable. Game counts do not imply usable timeline/metric counts. `available:true` means the cache read succeeded, not that a sufficient or nonempty sample exists.
- Prompt: `{id,match_id,seconds,title,question,evidence,kind}`; kinds are `death_before_objective`, `early_death`, `gold_swing`, `lead_lost`. These describe cached event timing/team snapshots, never mistake verdicts, cause attribution or recommended plays. Empty prompts are not proof of correct decisions; missing timelines are not games without events.
- Context `match`: `{match_id,game_start,duration,champion_id,role,patch,queue_id}`. Event: `{seconds,kind,label,side}`; kinds are `death|monster|building|gold`, sides are `us|them` relative to the linked player. Events/prompts use match clock regardless of a review's saved clock basis.

### Captured windows, cache bounds and privacy

Tracking is explicit opt-in, not a side effect of viewing/saving a plan, opening a disclosure or refreshing. Start captures the current linked PUUID, submitted filters and the **saved** plan's `games`. Baseline IDs freeze the latest up-to-N matching cached games whose end is strictly before `started`; later missing baseline rows remain missing. Practice uses the **first N** matching known completed games whose start is strictly after `started`, ordered by ascending game start and match ID, not newest-N. Millisecond match timestamps are compared with the full fractional-second start; already-running same-second matches cannot enter practice. Ordinary plan edits/archiving do not change the captured filters, start, game count or baseline IDs. Only an explicit restart replaces them.

Eligibility requires a supported queue, explicit raw `mapId:11`, classic mode, non-remake status, positive start time, duration 300..28800 seconds and completion by the read time; neither a queue guess nor a missing timeline establishes eligibility. Options and baseline/practice candidate searches each inspect at most 200 normalized candidates (one extra lightweight row detects truncation); raw map verification happens within that bound. `truncated` reports candidate-search truncation, not an exhaustive-history guarantee. Even a non-truncated result describes only what is cached, not all Riot history. Progress reads at most 20 frozen baseline plus 20 practice digests; a plan review queue reads at most 20 (default queue ten), sequentially. Raw match verification is bounded to 512 KiB compressed/2 MiB decompressed per document; existing digest validation/decompression bounds still apply.

Only these explicit match endpoints open `store.DB_PATH`, through short-lived `mode=ro`, `query_only` connections with a small page cache, disk temporary work and no mmap. They never call `store.connect`/`store.init`, create or migrate the cache, fetch matches/timelines from Riot, train models or trigger background downloads. Missing/old/partial caches and unusable digests remain unavailable or per-metric null as appropriate. Ordinary bootstrap, CRUD, export and team reads still need no cache connection.

All cache-derived output is private to the authenticated member's current linked account; a guessed match ID is not authorization. Unlink/account switch keeps authored records and tracking links, but suppresses tracked cached rows/metrics and plan prompts until relinking the captured account or explicitly restarting. Personal/team notes may contain manually entered match labels without granting cache access. There is no team cache API, and no automatic inclusion in player/cohort responses, team copies or exports; only an explicit notes-only copy shares authored review text. Export includes stored tracking configuration/IDs only when links exist, not derived progress or cache payloads.

## Data validation

Unknown keys rejected, strings bounded and control characters rejected (allow normal tabs/newlines in prose), finite numbers only, no booleans accepted as numbers. Enforced limits in `training.py`: title 120 characters, prose 4000, label/identifier 160, normalized entry JSON 32 KiB UTF-8; 200 quota-counted records per member (personal plus authored team docs in currently active memberships), 100 per team, 10 active/pending team memberships per member, 20 active/pending members per team (including owner). Titles, identifiers, lesson question/answer, puzzle prompt/choice labels and experiment hypothesis/change must be nonblank. Moment, observation and board-mark IDs must be unique within their document. Server validates referenced records exist and are accessible in matching scope; never trust guessable foreign IDs. Personal lesson/attempt/plan/session/experiment records may not be directly shared. Only reviews, puzzles and boards may have team_id. Teams may contain newly authored docs or explicit copies; sharing never changes a private document's scope. Copying a personal puzzle into a team clears its private `source_review_id`.

- **plans**: `{title,focus,role:'TOP'|'JUNGLE'|'MIDDLE'|'BOTTOM'|'UTILITY'|'',champion:string,workout_id:string,minutes:int 1..120,games:int 1..20,status:'active'|'archived'}`. At most one active plan per member, preserve old plan as archived when a new plan becomes active.
- **sessions**: `{plan_id:string|null,workout_id:string,minutes:int 0..240,repetitions:int 1..100,result:number|null,unit:string,focus:string,reflection:string,adhered:boolean,role:string,champion:string,patch:string}`. Result is finite −1,000,000,000..1,000,000,000 or null; zero is valid, missing is null. `workout_id` must be one of the catalog IDs (also for plans). References to plan validated.
- **reviews**: `{title,match_id:string,source_label:string,time_basis?:'video'|'match',moments:[{id:string,seconds:number 0..28800,title,known,options,decision,outcome,lesson,annotations:[{kind:'arrow'|'circle'|'text',x:number 0..1,y:number 0..1,x2:number 0..1,y2:number 0..1,text:string}]}]}`. Max 50 moments, max 30 annotations/moment. `time_basis` defaults to `video` when omitted (not null); legacy reviews receive this default on read without rewriting stored rows. Only the clock basis is persisted alongside numeric timestamps, never a calibration offset/anchor or cached-context payload. The server validates supplied numbers/basis, not a local video's calibration; all-moment conversion is a browser responsibility below. No media fields, file metadata or video content are stored; the optional on-device video uses a temporary Blob URL, revoked on replacement/detach/disposal and never persisted or uploaded. `match_id` and `source_label` reject paths/URLs; the label is user-supplied, never derived from the selected filename. Free-text notes remain user-authored, so review them for private information before sharing.
- **lessons**: `{question,answer,source_review_id:string|null,due:int Unix seconds,interval_days:int 1..365,repetitions:int 0..1000}`. `due` is bounded to 0..253402300799. Creation initializes due=now, interval_days=1, repetitions=0; editing validates the submitted scheduling fields but preserves the stored schedule. Grading retains question/answer, increments repetitions up to 1000, and sets due=now+interval_days×86400. Again sets 1 day; on an ungraded lesson Good/Easy sets 1/4 days, while after any prior grading Good/Easy doubles/triples the previous interval up to 365 days.
- **puzzles**: `{title,prompt,context,choices:[{label,tradeoff}],discussion,source_review_id:string|null,seconds:number|null}`. 2..5 choices, multiple reasonable answers; no invented ground-truth win labels. Private or explicit team copy.
- **attempts**: `{puzzle_id:string,choice_index:int 0..4,reason,reflection}`. Can reference authored or catalog puzzle; server checks choice index against referenced puzzle. Only personal.
- **experiments**: `{title,hypothesis,change,measure,unit,better:'higher'|'lower',role,champion,patch,phase:'baseline'|'practice'|'complete',observations:[{id:string,date:'YYYY-MM-DD',phase:'baseline'|'practice',value:number 0..100000,adhered:boolean,context:string}]}`. Max 100 observations, no causal/promotion claims. The server stores validated observations; the JS summary preserves empty groups as null. Omit unmeasured observations rather than inventing zeros; stored observation values are required numeric values.
- **boards**: `{title,notes,marks:[{id:string,kind:'arrow'|'ward'|'position'|'text',x:number 0..1,y:number 0..1,x2:number 0..1,y2:number 0..1,label:string,team:'blue'|'red'|'neutral'}]}`. Max 100. Original strategy diagram, no live tracking. Accepted team members may edit shared boards; creator edits own reviews/puzzles. Owner can moderate/delete.

## Static catalog

Workouts: IDs `last-hit`, `recall`, `jungle-clear`, `vision-setup`, `review-rotation`, `trading-window`. Each `{id,title,roles:[],minutes,goal,steps:[],measure,unit,tip}`. Workouts are instructions for manual practice INSIDE League. Avoid pass/fail CS or promotion targets; compare consistent setups. Catalog authored text-only decision puzzles have the same data fields above plus id. Use IDs `recall-window`, `objective-trade`, `unsafe-wave`; explain context-dependent alternatives rather than scoring one guaranteed answer.

## Browser module contract

Script order app.js, insights.js, training.js, training-review.js, training-team.js, training-lab.js. Extras register render functions; no automatic requests at file load. Existing app.route calls `Training.canLeave()` before route replacement, `showTraining()` for #/practice paths, and `Training.dispose()` before accepted route/login replacement; explicit logout checks `canLeave()`, while forced session expiry disposes without confirmation. No extra profile tabs.

`window.Training` (owned by training.js):
- `register(name, renderer)`, renderer signature `(root, ctx)`.
- `ctx = {current:()=>boolean, request(path,options), bootstrap, section, id, params:URLSearchParams, cleanup(fn), refresh:async()=>bootstrap, status(message,error=false), save(kind,data,existing=null,teamId=null), remove(entry), markSaved(form), guardDirty(predicate)}`. `guardDirty` returns an unregister function for canvas/out-of-form drafts; `markSaved` explicitly updates a successfully saved form's dirty baseline. `request` uses app.api and current predicate, restricts paths to `/api/training`, and aborts on disposal. `save` returns entry, calls the POST/PUT contract and keeps bootstrap personal entries synchronized. `remove` requires current revision. `refresh` reloads bootstrap explicitly, never an editor; saving an active plan also reloads affected plan list pages to pick up archived predecessors' revisions without redrawing editors. Every awaited caller checks current before DOM writes.
- Shared helpers: `Training.esc`, `Training.field(label, html)` optional; standard use app.js esc().
- `Training.canLeave()` checks pending writes and unsaved form/custom drafts before route/logout replacement. `Training.dispose()` aborts requests, cancels media/listeners/timers and clears per-route state. Async results also guard nav, username, root connectivity. Drafts are page-local, not autosaved or stored in localStorage; unsaved forms warn on navigation/browser leave, but forced session expiry clears them. Failed saves preserve entered text. 409 explains reload rather than silently overwriting or automatically retrying a PUT; explicit reload/discard requires confirmation.
- `showTraining()` parses `#/practice` hub; `#/practice/review[/id]`, `#/practice/lessons`, `#/practice/puzzles`, `#/practice/team[/id]`, `#/practice/experiments`, `#/practice/lab`. Register names `review`, `lessons`, `puzzles`, `team`, `lab`. Hub and experiments owned by training.js.
- Old `#/practice/lasthit` -> hub with last-hit workout preselected; `#/practice/dodge` -> trading-window workout. Query `?focus=...&role=...&match=...` prefills only new forms with escaping, never auto-saves or sends to other viewers. `#/practice/review?match=...` is used from match fold-outs. Review-queue links add encoded `at`/`prompt` focus parameters only: no context auto-request, moment creation, untrusted query text in notes or save; the requested row is highlighted only after an explicit cached-context load.
- CSS shared new training.css owned by primary, classes `training`, `training-head`, `training-grid`, `training-card`, `training-form`, `training-actions`, `training-status`, `training-muted`, `training-details`, `training-list`, `training-video`, `training-overlay`, `training-board`, `training-table`, `training-inline`.

### Match tools and local review clock behavior

The hub's native match-tools disclosure mounts without a match request. **Load cached match progress** explicitly reads options/progress; **Find cached review prompts** explicitly reads the chosen plan/recent-solo scope. Neither saves plan/filter drafts or starts tracking. Changing scope/active plan clears stale results; async writes check route, member, selected plan and request sequence. Start/restart and stop use the saved revision, merge the returned plan revision into local saved state and preserve live editor drafts/focus instead of redrawing them. An in-flight plan save blocks a tracking mutation; a 409 preserves drafts for explicit comparison/reload. Ordinary saves must not silently restart tracking or expand its captured game window.

`training-review.js` stores a calibration offset only in route-local memory: `video_seconds = match_seconds + offset`. A manual anchor requires finite numeric playback/game times in range and a playable local recording; blank/invalid inputs are not coerced to zero. Reset calibration when video is replaced/detached, another/new/reloaded review is loaded, match ID changes or the route is disposed. Do not send/persist an offset, anchor, media metadata or Blob URL in requests, exports, team copies or localStorage.

Changing a review's `time_basis` confirms and validates conversion of **every numeric moment timestamp** (and a touched new-moment timestamp) before atomically applying anything; it is never just a relabel. Converting between populated bases requires local alignment. Reject out-of-range conversions without partial edits and leave the old basis/timestamps intact on cancellation/failure. Saving is still explicit. Match-clock jumps/use-current-playback convert through that offset; missing alignment or a time outside the recording is reported unavailable, not clamped to zero. Same-basis video operations need no anchor. Saved team review copies preserve basis and display its clock label; derived lessons/puzzles include the basis label in their authored question/context and remain independent if the source review later changes basis.

**Load cached match events** is explicit, scoped to the entered match ID/current linked account and guarded against stale editor/match/route/member responses. Returned times are always match-clock times. Loading or following query focus never edits notes; **Create review moment** explicitly converts a chosen cached event/prompt into the review's basis and appends an unsaved moment without replacing existing moments/annotations. It needs calibration when converting to video clock. Retrospective evidence is placed in the outcome field; the what-was-known field stays blank for the player to author without hindsight. A separate Save review persists it. A failed/404/missing-timeline context request leaves typed notes intact and does not reveal another account's match or trigger a Riot call. Team review views never request personal cached context.

## Ownership and deletion

Member-quota accounting uses the same helper for creation checks and workspace counts. Revoked/left-team contributions retain their authorship, team storage and access restrictions but no longer count against the member quota. Pending re-invitations do not count them; accepted rejoin counts them again. If rejoining takes the member over quota, creation is blocked but accessible-record editing/deletion remains available. Team caps remain enforced independently.

Lazy additive tables in auth.DB_PATH (users.db), including `training_plan_links`, no import-time DB work and no production file touched during tests. `training_plan_links` stores one captured account/filter/window/baseline configuration per personal plan, separate from ordinary plan data. Normal unlink/account switch does not destroy user-authored training notes or these links; cache-derived progress remains hidden until relink/restart as described above. The auth CLI calls `erase_member(db,username)` before deleting the member, inside the same BEGIN IMMEDIATE transaction without changing existing auth foreign-key behavior. This erases that member's own docs (personal and team), memberships and owned teams, including teammates' docs in those teams. Other members' independent copies survive; leaving/removal from a team alone does not erase authored team docs. Deleting a plan cascades its tracking link; member erasure explicitly cleans links even on auth's FK-off connection. Deleting plans/reviews detaches nullable references on surviving sessions/lessons/puzzles and bumps their revisions; attempts retain historical puzzle IDs without granting source access. Services use foreign_keys ON on their own connections and guard member existence, accepted membership, references, quotas and writes transactionally. Ordinary training workspace/CRUD/export/team reads have no Riot/cache dependency; only the explicit private match routes read the cache, never Riot.

## Non-goals for this release

No local desktop recorder, server video uploads, AI analysis, monetization, external footage scraping, public team directories, live overlay recommendations, or claims of Riot approval. Explain these limits; do not expose dead buttons or scaffold placeholders as finished features.
